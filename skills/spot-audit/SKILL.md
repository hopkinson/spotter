# 阶段审计

## 确定范围

- `spot-audit <起点>` 以用户给出的 Git 提交、标签或分支为起点，检查该阶段的提交、暂存和未暂存改动，以及未忽略的新源码与配置。分支间比较用共同祖先作为起点。
- 未指定起点时，使用能明确识别的项目默认分支与当前分支的共同祖先。当前就在默认分支上、无法确认基线或无法确定共同祖先时，先请用户指定起点或选择全仓审计。
- `spot-audit --full` 检查当前工作区的整个仓库。用户指定子目录时，从该范围的入口出发，追踪必要的上下游。先读项目说明、依赖、入口和测试，再沿鉴权、外部输入、数据写入及后台任务等高影响路径深入。

## 检查并报告

读取 `../../bundled-skills/spot-ponytail-review/SKILL.md`，沿用其中与正确性、安全、负载、测试和性能有关的检查项和证据标准。

- 沿真实调用链确认风险。优先查越权、注入、密钥暴露、行为回归、数据丢失和并发问题，再检查高风险测试缺口和实际性能问题。
- 先报告实际范围和基线。发现按严重程度编号，每条给出文件与行号、触发条件、影响和最小修法，并区分已复现与静态确认。证据不足的疑点单列为待验证，注明遗漏的范围和无法执行的检查。
- 只读检查。验证可使用确认安全的本地检查或隔离环境中的用例。项目文件、Git 状态、生产数据和外部服务只做读取；报告留在当前会话，修复另行发起。

## 审计收尾流转
- 发现高危/阻断级漏洞时：在【下一步操作】中直接提示：`调用 spot-bug 针对第 X 项高危问题制定修复`。
- 无严重漏洞时：在【下一步操作】中直接提示：`调用 spot-release 推进发布流程` 或 `回复「确认完毕」结束审计`。
