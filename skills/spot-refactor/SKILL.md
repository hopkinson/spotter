# 重构检查与资产瘦身

`spot-refactor [路径] [--clean] [--structure]` 检查指定路径或全仓代码健康。只读分析，排除生成文件、构建产物与第三方依赖。

支持细分模式（默认两者兼顾）：
- `--clean`：专注闲置资产与死代码扫描（资产瘦身）。
- `--structure`：专注大文件膨胀与重复逻辑（架构重构）。

---

## 1. 结构与代码重构 (`--structure`)
- **大文件与膨胀模块**：优先看近期频繁变动、快速变长或单文件过大的手写源码。
- **职责混杂与重复实现**：读取 `../../bundled-skills/spot-ponytail-review/SKILL.md` 标准，识别跨多处同步修改的重复规则、过度封装或多余胶水层。
- **输出**：说明维护代价、拟精简/抽离范围，并标明守护测试。

## 2. 闲置资产与健康巡检 (`--clean`)
- **孤立文件与未引用模块**：全仓扫描无任何上游 import/require 导入的源码文件、死导出及未被入口调用的内部函数。
- **未使用的静态资源**：`public/` 或 `assets/` 中无代码引用的死图片、字体与废弃图标文件。
- **孤立状态与组合函数**：未被任何页面、组件或 API 消费的废弃 Store、Composable 或 Hook。
- **过期文档与空目录**：排查已脱离现有业务、无代码关联或示例已失效的历史文档与空目录。
- **死依赖与幽灵依赖**：检查 `package.json` 中已安装但源码从未引用的包，以及源码引用但未声明的隐式依赖。
- **过期技术债与临时标记**：汇总滞留的 `TODO` / `FIXME` / `shortcut:` 注释，标注已实现或已失效的标记。
- **僵尸配置与环境变量**：比对配置声明（如 `.env.example`、config 模版）与代码实际消费点，标记无消费项。
- **失效测试与跳过用例**：排查测试已不存在组件的陈旧用例，以及长期被 `.skip()` 忽略的测试。
- **动态加载与反射防线**：识别动态 `import(\`...\`)`、`<component :is="...">` 或动态路由模式；存在间接引用嫌疑时标为 `[需确认/可能存在动态加载]`，严禁静默误删。

## 检查收尾流转
- 按公共规则「统一收尾」选择一个首选候选，不同时排列所有入口。
- **有结构重构项时**：按编号标出有具体维护成本的候选，提示 `回复「重构第 X 项」`，明确下一阶段先准备拟议 diff 与等价性断言，不直接改业务代码。
- **有闲置资产/健康问题时**：输出分类清单与无引用等安全依据，提示 `回复「清理第 X 项」` 或有明确编号范围的 `回复「批量安全清理」`；明确先展示删除清单与验证方案，等开工确认后才剔除。
- **无重构与清理项时**：报告本次范围内未发现需处理项，自然结束，不把有限检查宣称为全仓健康。

## 原地承接与守护防线
当用户指定重构或清理时，直接原地承接实施，不套用需求草图：
1. **测试与构建防线**：
   - 结构重构：若无测试覆盖，**必须先补写轻量守护测试**锁定原行为。
   - 闲置资产删除：剔除前后必须执行类型检查（如 `tsc --noEmit`）或生产构建，确保零破坏。
2. **拟议 diff 与等价断言**：读取 `../../bundled-skills/spot-ponytail/SKILL.md` 给出最小改动 diff 或删除文件清单，并附带等价性说明。
3. **开工与闭环**：用户回复「开工」一次确认后执行改动，重跑测试或构建通过后，在【下一步操作】中推荐调用 `spot-review` 做最终审查与把关（`【下一步操作】/spot-review`）；有阻断项直接修复并复测，全部通过后交付。
