# 功能全景梳理

`spot-trace <功能名或模块>` 只读拆解功能的全景走查路线（用户提问「整理 xxx 功能」、「梳理 xxx 链路」时触发）。不修改业务代码。

读取 `../../bundled-skills/spot-before-after-sketch/SKILL.md`（未找到时退回本机同名版本），用其草图规范展示界面与交互。

按以下 5 部分按序输出，保持信息紧凑，直入主题：

## 1. 界面/场景草图
- 使用纯文本 ASCII 框图画出该功能涉及的核心页面、区域布局或弹窗线框。
- 标出核心操作元素（按键、输入框、展示字段、状态指示）。如果是无界面功能（纯后台 API/批处理），画出数据输入输出场景卡片。

## 2. 交互状态流转
- 提炼用户操作或系统触发的主干路径：`触发动作 → 状态迁移 → 结果反馈`。
- 覆盖关键边界分支（Loading、空数据、校验失败、权限拦截、网络异常）。

## 3. 调用与数据链路
- 沿端到端执行流追踪拓扑：
  `触发入口 (UI/API) → 路由/中间件 → 控制器/服务层 (Service/Logic) → 数据模型/缓存/存储 (DB/Storage) → 外部服务/事件派发`
- 标出关键入参和返回数据结构的核心字段。

## 4. 涉及代码清单
- 查找当前工作区手写源码，列出真实存在的文件路径、关键符号（组件/类/函数/Hook）及大致行号：
  - 前端/交互层：`path/to/file.tsx:line`（负责渲染与用户事件）
  - 业务/控制器层：`path/to/service.ts:line`（负责业务规则与流转）
  - 数据/配置层：`path/to/model.ts:line`（负责存储与契约）
- 严禁脑补不存在的文件或符号，必须基于代码搜索或图谱核实。

## 5. 实施/排查路线（带风险标注）
- 给出按依赖顺序排好的落地路线图，**在每一步前置标注风险等级**：
  - `[轻量/直改]`：局部文案、简单样式、可逆且无副作用的细微调整。
  - `[中风险/一次确认]`：独立组件交互、服务内部逻辑调整，直接给拟议 diff 确认。
  - `[完整路径/两次确认]`：涉及权限、金额、数据持久化、Schema 迁移或跨模块写入。
- 附带 1~2 条最容易踩坑的边界注意事项。

## 梳理收尾流转（自适应接力）
- 在【下一步操作】中直接提供极简指令：
  - 指定步骤实施：提示 `回复「开始实施第 X 步」`。会话将自动根据该步骤的风险标签自适应接力：
    - `[轻量]`：直接就地修改并跑验证；
    - `[中风险]`：就地给出该步拟议 diff 与测试，一次确认后开工；
    - `[完整路径]`：自动转入 `spot-plan` 开启需求草图与 diff 两次确认。
  - 做全局新功能：提示 `调用 spot-plan 开启需求澄清`。
  - 修特定链路缺陷：提示 `调用 spot-bug <具体现象>`。
