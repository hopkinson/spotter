# 周报生成（务实进度视角）

`spot-weekly [--limit <天数>] [补充说明]` 用于自动提炼面向领导的务实进度周报草稿。保持只读，不修改业务代码。

## 1. 采集与范围
- **确定时间区间**：指定 `--limit <天数>` 时回溯最近 N 天；未指定时默认统计当前自然周（周一 00:00:00 至今）。
- **锁定本人身份**：先读取当前 Git 用户身份（`git config user.name` 或 `git config user.email`）。
- **仅过滤本人提交**：运行 `git log --author="<当前用户>" --since="<起始时间>" --no-merges --oneline`，排除协作仓库中其他成员的提交。
- **结合补充输入**：结合用户在命令中附加的口头补充与上下文。

## 2. 归纳原则（个人事项维度，拒绝 commit 流水账）
- **聚合成个人事项**：严禁 1 条 commit 对应 1 个列表项。将针对同一模块或功能的多次提交（包含修复、调试、完善）合并为 1 个完整事项。
- **个人责任视角**：以“我负责的事项推进到了什么阶段”来叙述，而非罗列代码仓库改了哪些文件。
- **拒绝虚浮套话**：拒绝“赋能”、“业务价值”、“系统健壮性”等务虚词汇，不贴单测或函数名等技术细节。
- **核心三要素**：每项事项说清：**做了什么 + 推进到哪一步 + 当前进度状态**。

## 3. 标准输出结构
```markdown
# 工作周报（YYYY-MM-DD ~ YYYY-MM-DD）

## 一、 本周重点进展
### 【模块/项目名称】
- **事项名称**（进度：100% 已完成 / 80% 联调中 / 进行中）
  - 进展说明：本周完成了哪些具体功能/改造，当前交付到哪个阶段。

## 二、 风险与卡点
- **卡点事项**：卡在什么环节（如等外部接口、等依赖方联调、口径待确认），需要谁协调（无则填“暂无”）。

## 三、 下周计划
- **【模块/项目】事项名称**：下周具体推进的内容与目标。
```
