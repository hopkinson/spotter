# Bug 只读排查与诊断

`spot-bug <错误描述、报错堆栈或复现现象>` 专用于显式定位与诊断 Bug。本阶段保持**只读**，严禁擅自修改业务代码。

先读取 `../../bundled-skills/spot-diagnosing-bugs/SKILL.md`（未找到时退回本机同名版本），严格按其诊断规范建立反馈回路并追查根因。

按以下 4 步执行：

1. **复现与建立反馈回路**：
   - 根据用户提供的报错信息、堆栈或现象，先核实事实。
   - 寻找能稳定复现的最小路径（失败测试用例、单步脚本、curl 请求或 CLI 命令）。无法复现时，如实报告证据缺口与可能原因。
2. **追溯调用链路与定位根因**：
   - 沿端到端调用流追查：`触发入口 → 传参/校验 → 业务逻辑 → 故障点`。
   - 标出真实源码文件、关键函数及出错行号，指出“预期行为 vs 实际行为”以及引发缺陷的根本原因（`原因 X → 导致现象 Y`）。
3. **拟定最小方案与拟议 diff**：
   - 读取 `../../bundled-skills/spot-ponytail/SKILL.md`（未找到时退回本机版本），制定只触达病灶的最小修复方案。
   - 用一小段基于现有代码的拟议 diff 展示核心改动，不引入无关重构或多余封装。
4. **列出回归验证并等待确认**：
   - 列出防止复发的关键回归用例（`测什么情况 ｜ 应该看到什么结果`，最多 4 行）。
   - 保持代码未改动状态，明确提示当前排查结论，等待用户确认后再开始落测试与改代码。
